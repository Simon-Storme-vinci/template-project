1 Introduction

ImportantConsigne

1.1 Objectif

Ce projet met en place un reverse proxy avec autentification automatique. Nous utiliserons “Let’s Encrypt”, “Traefik” et Docker.

Traefik est le point d’entrée unique du serveur et du client : il reçoit les connexions sur les ports 80 et 443, route chaque requête vers le bon conteneur Docker selon le nom de domaine, et sert tout en HTTPS avec des certificats Let’s Encrypt qu’il obtient et renouvelle lui-même, sans intervention humaine.

1.2 Contexte et problématique

Sans reverse proxy, le serveur applicatif est exposé directement sur Internet, ce qui pose des problèmes de sécurité et de flexibilité. L’automatisation de certificats permet de ne plus se soucier de l’expiration, mais une supervision reste utile comme filet de sécurité.

2.1 Interfaces réseau VirtualBox

Chaque VM dispose de deux interfaces réseaux dans VirtualBox :

Interface Type VirtualBox Rôle
eth0 (enp0s3) NAT Télécharger les images Docker, installer les logiciels et contacter Let’s Encrypt
eth1 (enp0s8) Host-only (vboxnet0) Communication entre la VM et avec la machine hôte
Note

Pourquoi host-only et pas “réseau interne” ?

Le réseau interne (intnet) isole les VMs entre elles mais la machine hôte ne peut pas les joindre. Le host-only crée le réseau 192.168.56.0/24 partagé entre les VMs et l’hôte (192.168.56.1) : on peut ainsi ouvrir https://whoami.example.com dans le navigateur de l’hôte, et le correcteur peut faire de même depuis sa propre machine en reproduisant le TP.

Réglage VirtualBox : Paramètres de chaque VM → Réseau → Carte 2 → Réseau privé hôte (host-only) → vboxnet0. Si vboxnet0 n’existe pas : Fichier → Outils → Gestionnaire de réseau → Créer.

Note

Pourquoi garder la carte NAT ?

Traefik doit contacter, en sortie, les serveurs de Let’s Encrypt et l’API de votre hébergeur DNS pour obtenir les certificats (défi DNS-01). Le NAT fournit cet accès Internet sortant. Aucune connexion entrante depuis Internet n’est nécessaire : les enregistrements DNS pointent vers l’IP privée 192.168.56.10, accessible uniquement depuis votre machine.

VM Interface IP Masque Remarque

2.3 Configuration des IPs fixes

Sur vm-proxy, éditer /etc/network/interfaces :

nano /etc/network/interfaces
# Interface NAT — DHCP (laisser tel quel)
auto enp0s3
iface enp0s3 inet dhcp

# Interface host-only — IP fixe
auto enp0s8
iface enp0s8 inet static
    address 192.168.56.10
    netmask 255.255.255.0

Vérifier que le service networking est actif et que la configuration utilise bien ifupdown.

Appliquer la configuration (de préférence depuis la console VirtualBox) :

systemctl restart networking

# Vérifier les addresses IP :
ip a 

# Vérifier spécifiquement l'interface host-only : 
ip a show enp0s8
# Le résultat attendu est => inet 192.168.56.10/24 ...

2.4 Vérification de la connectivité

Avant toute installation, vérifier que tout le monde se voit :

# Depuis vm-proxy, tester la communication avec la machine hôte :
ping -c 3 192.168.56.1
# Résultat attendu : 3 paquets reçus, 0 % de perte.

# Depuis la machine hôte, pinger vm-proxy.
ping -c 3 192.168.56.10
# Le résultat attendu est => 3 paquets reçus, 0 % de perte.

# Vérifier l'accès Internet depuis vm-proxy :
ping -c 3 google.com
# Cette vérification permet de s'assurer que l'interface NAT fonctionne correctement.
Avertissement

Problème fréquent : si le ping échoue, vérifier que la carte 1 de la VM est bien configurée en NAT et que la carte 2 est bien attachée au réseau Host-only (vboxnet0). Vérifier également que l’interface enp0s8 possède bien l’adresse IP 192.168.56.10/24 et que la machine hôte possède une adresse dans le même sous-réseau (192.168.56.0/24).

Astuce

📷 Capture attendue : sorties des commandes ping montrant la connectivité entre la VM vm-proxy (192.168.56.10) et la machine hôte (192.168.56.1), avec 0 % de perte de paquets. Ajouter également une capture du ping vers Internet.

Astuce

Snapshot conseillé : une fois la configuration réseau fonctionnelle et les tests de connectivité réussis, prendre un snapshot VirtualBox nommé « réseau OK » sur la VM vm-proxy, avant de passer à l’installation de Docker et de Traefik.
